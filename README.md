# アイドマ営業クエスト ⚔️

営業マン向けの RPG 型教育 Web アプリです。PC ブラウザとスマートフォンの両方で動作します。
アイドマ学園で「虎の巻」を学び、全7大業界の魔物（見込み顧客）と3フェーズの商談バトルで戦い、村人から伝説の勇者を目指します。

## 起動方法

```bash
npm install
npm run dev        # http://localhost:5173 （--host 付きなので同一LANのスマホからもアクセス可）
npm run build      # 型チェック + 本番ビルド
```

## 画面構成

- **アイドマ学園**：虎の巻3講義（冒頭5秒の心理学／「検討します」の深掘り法／伴走型内製化支援の価値）。スライドはスワイプで送れ、最後の確認問題に正解すると EXP と G を獲得できます。Lv.2 でギルドが解放されます。
- **業界用語集**（学園内）：営業基礎＋7業界の計48語。4択の用語テストに初めて正解すると EXP・G を獲得し、正解した用語は図鑑で意味と使いどころを読めます。
- **営業偏差値**：虎の巻の習得・用語の習得・用語テストの正答率から算出（38〜78）。学ぶほど上がります。
- **冒険者ギルド**：7業界14件の討伐依頼。業界ごとにタブを切り替えられ、難易度は初級〜魔王級。推奨Lv−1 から受注でき、討伐済みの依頼は報酬半減で再戦できます。
- **営業バトル**：Phase1 業界動向フック → Phase2 深掘りヒアリング → Phase3 解決価値提案。
  - 正解時：黄金スラッシュ＋ダメージ＋「なぜ刺さるのか」解説。フェーズ内の初回正解は会心の一撃になります。
  - 不正解時：自キャラが被弾し、顧客の反発セリフと「失注リスク」解説が出ます。
  - 補助：職業スキル（誤答消去・インサイト表示）と回復薬（50G）。
  - 攻撃演出：キャラクターは「構え → 振りかぶり → 振り下ろし」のコマで攻撃し、誤答時はモンスターも同じ流れで反撃します。
- **勇者・転職**：キャラクター表示（ピンチ/ホイールでズーム）、男女タイプの切り替え、主人公名の変更、転職の神殿、BGM設定。
- **冒険の書（セーブ／ロード）**：画面上部の本アイコンから、3つの枠に進行を記録・再開できます。記録日時・レベル・職業・討伐数が残ります（端末のブラウザに保存）。最初の画面の「冒険の書から再開する」からも読み込めます。

## 紹介先リサーチ（research.html）

アイドマの受注一覧 CSV から、紹介先候補の企業を探す別アプリです（ゲームとは独立）。`npm run dev` 後に `http://localhost:5173/research.html`、公開後は `<公開URL>/research.html` で開きます。

- **使い方**：受注一覧 CSV（管理画面からの出力そのまま、UTF-8 / Shift_JIS）を読み込み、繋がりたい業界・キーワードを入力するか業界チップを選ぶと、おすすめ順に企業を表示します。
- **表示項目**：企業名、代表者（役職・氏名）、電話番号、メール、HP、住所、事業内容（サービス/商品名＋受注経緯から抜き出した会社紹介）、取引履歴、社内担当者。
- **おすすめの理由**：業種・商品・受注メモのキーワード一致、業界の一致、橋渡し役（例：建設とつながりたい → 不動産会社）、支援中かどうか、受注回数・直近の受注・累計受注額、従業員規模、連絡先の揃い具合、解約歴の注意を組み合わせて点数化し、理由を文章で表示します。社長（決裁者）の想定カラーが登録されていれば、話し方のヒントも出します。
- **絞り込み・出力**：地域（都道府県）、取引状況（解約先を除く / 支援中のみ / すべて）、支援担当者（姓だけでも可。「受注担当者・責任者も含める」で範囲を広げられます。業界を指定せず担当者だけ入れると、その人の担当企業を一覧できます）、連絡先ありのみ。結果は CSV で出力できます。
- **データの扱い**：CSV はブラウザの中だけで処理し、IndexedDB に保存します（外部送信なし）。リポジトリに顧客データを含めないよう `*.csv` は `.gitignore` 済みです。
- **ロジック**：`src/research/`（`industries.ts` に業種の大分類と「どの業界がどの業界の橋渡し役になるか」、`recommend.ts` に点数と理由の作り方）。テストは `src/research/__tests__/`。

## 数字分析・改善ナビ（analysis.html）

スプレッドシートで管理している KPI（架電数 → 接続数 → アポ数 → 商談数 → 受注数 → 売上 など）から、目標達成のためにどこを改善すべきかを出す別アプリです（ゲームとは独立）。`npm run dev` 後に `http://localhost:5173/analysis.html`、公開後は `<公開URL>/analysis.html` で開きます。

- **読み込み**：スプレッドシートの範囲をコピーして貼り付け（タブ区切り）／CSV ファイル（UTF-8 / Shift_JIS）／Google スプレッドシートの URL（リンクを知っている全員が閲覧できるシートのみ）。表の上のタイトル行は飛ばし、指標が縦に並んだ表は自動で縦横を入れ替えます。
- **表の読み方**：列名から役割（行動量・接続・アポ・商談・提案・受注・売上）を推定し、ファネル順に並べます（設定で変更可）。「目標」「計画」「予算」の行や「アポ目標」のような列は目標として、「合計」行は除外します。担当者・月など文字の列で比べる単位と絞り込みを選べます。
- **分析**：達成率・不足額、営業日の経過からの着地見込み、今の転換率のまま目標に必要な各段の数（逆算）、各転換率の基準（手入力 > 目標から逆算した率 > 行どうしの上位25%水準）との比較。基準まで上げたときの増分で改善ポイントを順位付けし、段ごとの「疑うこと・改善アクション・効果の確認方法」を表示します。月の表なら直近と過去平均の比較、担当者の表なら一人ひとりの一番の課題も出します。
- **アイドマのヨミ表（コックピット）**：「期間・当日アポ・新規・提案取得・提案訪問・ヨミ取得・ヨミ訪問・受注・受注金額」の表が何ブロックも並ぶシートをそのまま貼り付けると、ブロックを「区分」（例：`表1 7/27〜10/23`、`当月 10/24〜11/20`）ごとの1枚の表にまとめて読みます。「当月実績」の行は直前の行の当月分として扱います。月次ミッションを目標に使えるほか、右側のヨミ集計（ランク・確度・金額・計上）から計上見込み・ミッションまでの差・ランクを1つ上げたときの効果を出します（`src/analysis/cockpit.ts`）。
- **案件フィルター（画面上部のタブ、`analysis.html#deals`）**：ヨミ表の案件一覧（1行＝1案件）を貼り付けると、「現在」「属性」「アポチャネル」「提案商材」の列を最優先に、選択肢の少ない列を自動で絞り込みボタンにします（複数選択可、各ボタンの数字はほかの条件で絞った件数）。日付の列で期間（今月・先月・直近3か月）、キーワードで企業名やメモも絞り込めます。該当件数・金額合計・1件あたり、列ごとの内訳（行クリックでその値に絞り込み）、2列のクロス集計、月ごとの件数、該当案件の一覧（並べ替え・CSV 出力）を表示します（`src/analysis/deals.ts`、`DealsApp.tsx`）。
- **共有**：分析結果をテキストでコピーでき、会議資料やチャット・Claude への相談に貼り付けられます。
- **データの扱い**：計算はブラウザの中だけで行い、表と設定は localStorage に保存します。
- **ロジック**：`src/analysis/`（`table.ts` に表の読み取りと役割の推定、`cockpit.ts` にヨミ表の読み取り、`analyze.ts` に逆算と改善ポイントの計算、`playbook.ts` に改善アクション）。テストは `src/analysis/__tests__/`。

## セーブシステム（src/save）

ゲームの状態は zustand（`src/store/gameStore.ts`）が持ち、保存・読み込みはすべて `SaveManager` に集約しています。

- **保存先**：Web は IndexedDB（主）＋ localStorage（ミラー）。Capacitor でネイティブ化した場合は Preferences（主）＋ localStorage。どれも使えない環境では「保存されません」と表示します。
- **3世代書き込み**：各スロットを `current / backup / tmp` で持ち、`tmp に書く → 読み戻し検証 → current を backup へ → current に書く → tmp を消す` の順で更新。起動時は全保存先×3世代から、チェックサムが正しく最も新しいものを採用します。
- **自動セーブ**：ゲーム状態の変化を監視してまとめて保存（進行 150ms / 画面移動・設定 1秒）。戦闘終了・クエスト受注・新規ゲーム・手動セーブ・バックグラウンド移行（`visibilitychange` / `pagehide` / Capacitor `pause`）では即時保存。
- **起動判定**：初回起動 / 前回の続き / バックアップから復旧 / 旧形式から移行 / 破損 / データ消失 / 保存領域なし。破損・消失時は自動で初期化せず、冒険の書・保存コード・新規開始から選んでもらいます。
- **saveVersion と Migration**：`src/save/migrations.ts` に版ごとの変換を追加します（v0 旧自動保存 → v1 旧冒険の書 → v2 現行）。アプリより新しい版のデータは読み込みを拒否します。
- **保存コード**：`AQS1:` で始まる文字列で、端末・ブラウザ・アプリ間の引き継ぎや控えに使えます。
- **複数タブ**：別のタブが新しい進行を保存したら、古いタブは上書きせず停止して通知します。

### ネイティブ化（Capacitor）するとき

```bash
npm i @capacitor/core @capacitor/preferences @capacitor/app && npm i -D @capacitor/cli
npx cap init "アイドマ営業クエスト" <バンドルID> --web-dir=dist
npx cap add ios && npx cap add android && npx vite build && npx cap sync
```
SaveManager は実行時に Capacitor の Preferences / App プラグインを検出して自動で使います（コード変更不要）。
