## 1. 現状

**このゲームには音が一切ありません。** 音源ファイルも1つも持っていません。

つまり STEP 11 は「既にあるものを整理する」のではなく、
**ゼロから作る**話になります。だからこそ、最初の設計が効きます。

## 2. ★ 最大の制約：ダウンロード版のファイルサイズ

このゲームの売りの1つは「**HTMLファイル1つで、どこでも遊べる**」ことです。
いまの `dist/tensei-arcana.html` は **276KB** です。

音を1つのファイルに埋め込むと、どうなるか計算しました。
（音声をHTMLに埋め込むと、データが約1.37倍に膨らみます）

### BGMを埋め込んだ場合

| ループの長さ | 音質 | 7曲の合計 | ビルド後のサイズ |
|---|---|---|---|
| 15秒 | 96kbps | 1.7 MB | 約 2.0 MB（**7倍**） |
| 30秒 | 96kbps | 3.4 MB | 約 3.7 MB（**13倍**） |
| 60秒 | 96kbps | 6.7 MB | 約 7.0 MB（**25倍**） |
| 120秒 | 96kbps | 13.5 MB | 約 13.8 MB（**50倍**） |

**まともな長さのBGMを7曲入れると、ファイルが25〜50倍になります。**
スマートフォンで開くのに時間がかかり、「1ファイルで手軽」という長所が消えます。

### 効果音を埋め込んだ場合

| 内容 | サイズ |
|---|---|
| 効果音1個（0.3秒・モノラル64kbps） | 約 3 KB |
| 30個 | 約 **99 KB** |

**効果音は埋め込めます。** 276KB → 375KB（+36%）で収まります。

### 結論

> **効果音は埋め込める。BGMは埋め込めない。**

この事実から、設計を決めます。

## 3. 解決策：音を「作る」か「持つ」かを選べる形にする

### 3-1. 考え方

音源を**固定で持たず**、「この音はこう鳴らす」という**指示**を登録します。
指示には3種類あります。

| 種類 | 中身 | サイズ | 使いどころ |
|---|---|---|---|
| `synth` | ブラウザに**その場で音を作らせる** | **0 バイト** | ダウンロード版・初期状態 |
| `data` | 音声データをHTMLに埋め込む | 実データ分 | 効果音 |
| `url` | 外部の音声ファイルを読む | 0（別ファイル） | Web版・アプリ版のBGM |

```
G.AUDIO_SOURCES = {
  bgm_title:   { kind:'synth', ... },              ← 0バイト
  bgm_battle:  { kind:'url', src:'audio/battle.ogg' },  ← 差し替え済み
  se_attack:   { kind:'data', mime:'audio/mpeg', b64:'...' },
}
```

**これが「差し替え可能な音源」の実体です。**
将来きちんとした楽曲を用意できたら、**この表を書き換えるだけ**で済みます。
ゲーム側のコードは1行も変わりません。

### 3-2. `synth`（その場で作る音）とは

ブラウザには音を合成する機能（Web Audio API）が標準で入っています。
音階と長さのデータを渡せば、**ファイルなしで音楽が鳴ります**。

```
bgm_title: {
  kind:'synth', tempo:96, wave:'triangle',
  melody: 'C4/4 E4/4 G4/2 ...',      ← 文字なので数KB
}
```

- **サイズ：ほぼ0**（楽譜データ数KBのみ）
- **音質：ファミコン風のレトロな音**になります
- 権利の問題がありません（自分で書いた楽譜なので）

### 3-3. 正直に申し上げる注意点

**`synth` で作れるのは「ファミコン風」の音です。**
オーケストラ風や、現代的な劇伴の音にはなりません。

作品の雰囲気（転生・魔法学院・魔王討伐）を考えると、
本当は豊かな音楽のほうが合います。
しかし**いま音源が1つも無い**以上、選択肢は次の3つです。

| 案 | 内容 | 費用 | ダウンロード版 |
|---|---|---|---|
| **A** | すべて `synth`（ファミコン風） | 0円 | そのまま1ファイル |
| **B** | 楽曲を用意し、Web版・アプリ版だけBGMあり<br>ダウンロード版は `synth` | 楽曲費 | 1ファイルのまま |
| **C** | 楽曲を用意し、ダウンロード版もBGM入り | 楽曲費 | **7MB前後になる** |

**私の推奨は B です。**
理由：`synth` で作っておけば**いますぐ音が鳴り**、
あとから楽曲を買ったときに**表を書き換えるだけ**で差し替わります。
ダウンロード版の手軽さも守れます。

**ただし「ファミコン風の音でよいか」は、作品の方向性に関わるご判断です。**
実装前にお決めください。

## 4. スマートフォンでの制約（先に知っておくべきこと）

### ★ 制約1：iPhone は最初のタップまで音を鳴らせない

iOS・Android とも、**画面を1度も触っていない状態では音を鳴らせません**。
勝手に音が出る広告を防ぐためのブラウザの仕様です。

**対策**：音の準備だけ先に済ませ、
**タイトル画面で最初のボタンを押した瞬間**に音の出口を開きます。
プレイヤーには何も見えません。

これを設計に入れておかないと、**「iPhoneだけ音が出ない」**という
最も分かりにくい不具合になります。

### ★ 制約2：iPhone は音量を指定できない

iOSのSafariでは、`audio.volume = 0.5` のような**音量指定が無視されます**。
本体の音量ボタンでしか変えられません。

**対策**：音の再生を**すべて Web Audio API 経由**にします。
Web Audio の音量調整は iOS でも効きます。

> これは「`synth` を使うかどうか」とは別の話です。
> **ファイルの音を鳴らす場合も、Web Audio 経由で鳴らします。**
> STEP 12 の設定画面で音量スライダーを作る以上、これは必須です。

### ★ 制約3：マナーモードで音が消える（iOS）

iPhone の側面スイッチをマナーモードにすると、Web Audio の音は消えます。
**ブラウザ版では解決できません。**

アプリ版（Capacitor）では、iOS側の音声設定を変えれば
マナーモードでも鳴らせます。STEP 14 で扱います。

**ブラウザ版では「音が出ないときはマナーモードをご確認ください」と
設定画面に一文添える**のが現実的な対処です。

### 制約4：アプリを閉じたら止める

他のアプリに切り替えたときにBGMが鳴り続けると、非常に嫌われます。

**対策**：画面が隠れたら止め、戻ったら再開します
（`visibilitychange` を使用。既存のイベント管理の仕組みに乗せます）。

## 5. BGM（7曲）

| ID | 曲 | 鳴らす場面 | 雰囲気 |
|---|---|---|---|
| `bgm_title` | タイトル | タイトル画面 | 静か・期待 |
| `bgm_academy` | 学院 | 拠点・学院・ジョブ・ステータス | 穏やか・日常 |
| `bgm_town` | 街 | 街・ギルド | 賑やか |
| `bgm_field` | 探索 | 探索画面（STEP 9） | 旅・少し不安 |
| `bgm_battle` | 戦闘 | 通常戦闘 | 疾走 |
| `bgm_boss` | ボス戦 | ボス・昇格試験・魔王城の道中 | 重厚・緊張 |
| `bgm_final` | 決戦 | 魔王戦・エンディング | 壮大 |

### 切り替えの規則

- **画面ごとに曲を決める**（`G.UI.show()` の1か所で切り替え）
- 同じ曲が続くときは**鳴らし直さない**（ぶつ切りを防ぐ）
- 切り替えは**0.4秒かけて重ねる**（急に切り替えると耳障り）
- ストーリー再生中は**そのまま**（場面が細かく変わるため）

## 6. 効果音（9分類）

| # | 分類 | ID | 鳴らす場面 |
|---|---|---|---|
| 1 | 決定 | `se_ok` | ボタン・選択・モーダルの決定 |
| 2 | 取消 | `se_cancel` | もどる・やめる・閉じる |
| 3 | 物理攻撃 | `se_attack` | 斬る・殴る |
| 4 | 魔法 | `se_magic` | 詠唱と発動 |
| 5 | 被弾 | `se_hit` | ダメージを受ける |
| 6 | 回復 | `se_heal` | HP・MP回復、蘇生 |
| 7 | 状態異常 | `se_status` | 毒・麻痺・弱体・強化 |
| 8 | 獲得 | `se_gain` | レベルアップ・入手・依頼達成・試験合格 |
| 9 | 警告 | `se_alert` | 戦闘不能・全滅・失敗・エラー表示 |

### 組み込む場所は2か所だけ

調べたところ、**戦闘の効果音は1か所に集約できます**。

`screen_battle.js` の `playEvents()`（216行）が、
戦闘中のすべての出来事（ダメージ・回復・状態異常…）を
1つずつ処理しています。**ここに数行足すだけ**で、
戦闘の効果音がすべて鳴ります。

| 場所 | 対象 |
|---|---|
| `screen_battle.js` の `playEvents()` | 攻撃・魔法・被弾・回復・状態異常・戦闘不能 |
| `ui.js` のボタン処理 | 決定・取消 |

**戦闘エンジン（`battle.js`）には一切触れません。**

### 効果音が重なりすぎないようにする

全体攻撃で敵4体に同時にダメージが入ると、
被弾音が4つ重なって割れた音になります。

**対策**：同じ効果音は**60ミリ秒以内に2回鳴らさない**。
2回目以降は無視します。

## 7. 音の管理役（`G.Audio`）の設計

### 7-1. 使いかた

```
G.Audio.init()              最初のタップで音の出口を開く
G.Audio.bgm('bgm_battle')   BGMを切り替える（同じなら何もしない）
G.Audio.stopBgm()           止める
G.Audio.se('se_attack')     効果音を鳴らす
G.Audio.setVolume('bgm', 0.6)
G.Audio.setEnabled('se', false)
```

### 7-2. 必ず守ること：**音が無くてもゲームは動く**

```
音が使えない環境（古いブラウザ・テスト実行・音源が無い）
  → G.Audio は何もしないが、エラーも出さない
```

**理由**：音はゲームの「飾り」です。
音の不具合でゲームが遊べなくなるのは、本末転倒です。

具体的には：

- `AudioContext` が無い環境では、全メソッドが**静かに何もしない**
- 存在しない音IDを指定しても**落ちない**（開発時だけ警告）
- 音の読み込みに失敗しても**ゲームは続行**

`npm test` はブラウザを使わない検査も含むため、
**音の仕組みがテストを壊さないこと**も重要です。

### 7-3. 音量と設定の保存

| 設定 | 既定値 |
|---|---|
| BGM 音量 | 0.5 |
| 効果音 音量 | 0.7 |
| BGM ON/OFF | ON |
| 効果音 ON/OFF | ON |

**保存先は STEP 10 で作る `G.Storage` を使います。**
ただし**セーブデータには入れません**。

理由：音量は「その端末の好み」であって「冒険の記録」ではありません。
セーブに入れると、スロットを切り替えるたびに音量が変わってしまいます。

```
ta.settings   ← 音量・ON/OFF（端末ごと。セーブとは別）
ta.save.v2.*  ← 冒険の記録
```

設定画面そのものは STEP 12 で扱います。

## 8. 実装の順序

| 段階 | 内容 | 確認方法 |
|---|---|---|
| 11-1 | `G.Audio` の骨組み。**音は鳴らさない**（何もしない状態） | `npm test` が通る |
| 11-2 | 効果音を `synth` で9種類作る | 手で聞いて確認 |
| 11-3 | `playEvents()` と `ui.js` に組み込む | 戦闘して聞く |
| 11-4 | BGM を `synth` で7曲作る | 画面を巡って聞く |
| 11-5 | 画面切り替えと連動・重なり防止・アプリ切替時の停止 | 自動テスト |
| 11-6 | 音量・ON/OFF の保存（STEP 10 の `G.Storage` 使用） | 再読み込みで保持 |

**11-1 の時点では音が鳴りません。**
これは意図的です。「仕組みが入ってもゲームが壊れない」ことを
先に確かめてから、音を足します。

### 自動テストで確かめること

音そのものは自動で聞けませんが、**次のことは機械的に確認できます**。

- 音を切っても、すべての画面が正常に動くか
- 存在しない音IDを指定しても落ちないか
- `AudioContext` が無い環境で落ちないか
- 画面を切り替えたとき、BGMの指定が正しく変わるか（**鳴らさずに記録だけ確認**）
- 全体攻撃で効果音の呼び出しが間引かれているか
- 画面を隠したらBGMが止まるか

### 判断4について

**音は「遊べるかどうか」には関わりません。**
一方、STEP 10（セーブ）は**公開前に必ず必要**です。

限られた時間を使う順序としては、

```
STEP 10（セーブ）実装 → STEP 13（スマホ対応）→ STEP 12（設定画面）→ 音
```

のほうが、**公開に近づきます**。
音は「あると嬉しい」もので、「無いと出せない」ものではありません。

ただし**これはご判断です。**「音がないゲームは出したくない」という
お考えであれば、その順序で進めます。

## 10. この設計で守られること

- 戦闘エンジン（`battle.js`）には**一切手を入れません**
- 効果音の組み込みは**2か所のみ**（`playEvents()` と `ui.js`）
- **音が使えなくてもゲームは完全に動きます**
- 音源は**表を書き換えるだけで差し替えられます**
- 音量設定は**セーブデータに入れません**（端末ごとの設定として分離）
- ダウンロード版の**1ファイルという形は崩しません**
