## 1. なぜ必要か

いまゲームで戦える場所は**冒険者ギルドの依頼だけ**です。依頼はランクで絞られるため、

- ランクが上がらないと新しい依頼が出ない
- 昇格にはレベルが要る（例：C級はLv19）
- レベルを上げるには依頼をこなすしかない

という**行き止まり**ができます。訓練場（1AP・経験値のみ）で凌げますが、
「自分で行き先を選んで戦いに出る」体験がありません。

自由探索は、この穴を埋めると同時に、RPGとして当たり前の
**「どこへ行くか自分で決める」**を成立させます。

## 3. ★ 最重要：ゲーム経済への影響

**新しい稼ぎ口を足すと、既存のバランスが壊れる恐れがあります。**
実際の数字で確かめました。

### 依頼1件で本当にもらえる額

依頼の報酬は**戦闘の報酬とは別枠で加算**されます（`world.js:216 completeQuest`）。
つまり「敵から得る分」＋「依頼の成功報酬」の合計です。

| ランク | 1APあたり 金銭 | 1APあたり 経験値 |
|---|---|---|
| F | 127G | 92 |
| E | 290G | 266 |
| D | 372G | 398 |
| C | 757G | 661 |
| B | 1,397G | 1,256 |
| A | 2,216G | 1,885 |
| S | 4,173G | 2,480 |

### 探索1回（敵3体・1AP）を素のまま行った場合

| エリア | 金銭 | 経験値 | 同ランク依頼との比 |
|---|---|---|---|
| ラヴィン近郊の草原 | 44G | 92 | 金 0.35倍 / 経験 1.00倍 |
| ささやきの森 | 84G | 179 | 金 0.29倍 / 経験 0.67倍 |
| 風鳴りの洞窟 | 193G | 413 | 金 0.52倍 / 経験 1.04倍 |
| 古代遺跡ヴェルナ | 261G | 558 | 金 0.34倍 / 経験 0.84倍 |
| 嘆きの高原 | 811G | 1,736 | 金 0.58倍 / **経験 1.38倍** |
| 氷牙山脈 | 1,168G | 2,502 | 金 0.53倍 / **経験 1.33倍** |
| 魔王領境界 | 1,136G | 2,433 | 金 0.27倍 / 経験 0.98倍 |
| 魔界・黒曜の荒野 | 1,356G | 2,905 | 金 0.32倍 / 経験 1.17倍 |

### 結論

**金銭は問題ありません。** 探索は依頼の 0.27〜0.58倍しか稼げないので、
「武器を買うなら依頼を受ける」という動機は保たれます。これは良い形です。

**経験値だけ、中盤（嘆きの高原・氷牙山脈）で依頼を 1.33〜1.38倍上回ります。**
ここだけ放置すると、「依頼より探索でレベルを上げたほうが速い」状態になり、
学院の3年間（135日・総AP 405）という時間設計が緩みます。

### 対処（設計に織り込む）

> **探索で得る経験値に 0.85 倍を掛ける。**
> 金銭には倍率を掛けない（すでに十分低いため）。

これで全エリアが 0.57〜1.17倍に収まり、
**「稼ぐなら依頼、自由に動きたいなら探索」**という役割分担が成立します。

この倍率は1か所の定数にし、あとから測定して調整できるようにします。

## 4. データ構造の仕様

### 4-1. エリア定義（`src/data/areas.js` を拡張）

```
G.AREAS = {
  <エリアID>: {
    name        文字列   表示名（辞書キーにする：area.plains.name）
    icon        文字列   絵文字1つ
    lvRange     [下限, 上限]  推奨レベル。画面に「推奨 Lv1〜8」と出す
    map         { col, row }  地図上のマス位置（4列×2行のグリッド）
    unlock      解放条件（4-3 参照）
    ap          数値     出撃に要するAP（既定 1）
    encounters  [ { id, weight, min, max } ]   出現する敵と重み（4-2 参照）
    partySize   [下限, 上限]  1戦闘に出る敵の数（既定 [2, 4]）
    drops       [ { id, rate } ]   エリア固有の追加ドロップ（任意）
    boss        エリアボスの設定 または null（4-4 参照）
    desc        文字列   1〜2行の説明
  }
}
```

**いま `pool:['slime','rat',...]` と書かれている配列は、`encounters` に置き換えます。**
`pool` は重みを持てないため、Lv1のスライムとLv6の狼が同じ確率で出てしまいます。

### 4-2. 出現率の決めかた

```
encounters: [
  { id:'slime',     weight: 40 },
  { id:'rat',       weight: 30 },
  { id:'goblin',    weight: 20 },
  { id:'wild_wolf', weight: 10 },
]
```

- `weight` は**相対値**。合計が100である必要はありません（読みやすさのため100に揃える方針）
- 1戦闘につき `partySize` の範囲で敵の数を決め、その数だけ重み付き抽選します
- 同じ敵が重複して出てもよい（現在の依頼も `enemies:['slime','slime']` の形）

**重みの方針**：そのエリアの推奨レベル下限に近い敵ほど出やすく、
上限に近い敵は希少にします。「たまに強いのが出る」緊張感を作るためです。

**抽選は必ず `G.util.weighted()` を通します。**
`Math.random()` を直接呼ぶと、`npm test` のスナップショット照合
（乱数を固定して結果を突き合わせる仕組み）が使えなくなるためです。

### 4-3. 解放条件

```
unlock: { rank: 0 }                    ギルドランクF以上
unlock: { rank: 2 }                    ギルドランクD以上
unlock: { flag: 'graduated' }          卒業後
unlock: { rank: 3, flag: 'awaken' }    両方満たす
```

既存の仕組みをそのまま使います（`G.State.flag()` と `d.guild.rank`）。
**新しい進行管理を増やしません。**

| エリア | 解放条件 | 理由 |
|---|---|---|
| ラヴィン近郊の草原 | 最初から | 最初の行き先 |
| ささやきの森 | ランクE（Lv7） | 依頼で森に行った後 |
| 風鳴りの洞窟 | ランクD（Lv12） | |
| 古代遺跡ヴェルナ | ランクC（Lv19） | |
| 嘆きの高原 | ランクB（Lv27） | |
| 氷牙山脈 | ランクA（Lv36） | |
| 魔王領境界 | 卒業フラグ | 物語上、卒業まで入れない |
| 魔界・黒曜の荒野 | 卒業フラグ＋魔王領境界のボス撃破 | 最終盤 |

**解放されていないエリアも地図には表示します**（灰色＋鍵アイコン）。
条件も書きます。「次に何を目指せばいいか」が見えるほうが、
遊ぶ人にとって親切だからです。

### 4-4. エリアボス

```
boss: {
  id:        'area_boss_xxx'   G.ENEMIES のキー
  unlockAt:  5                 そのエリアを5回探索したら挑めるようになる
  firstClear:{ gold: 3000, item: 'xxx' }   初回撃破の特別報酬
  repeatable: true             2回目以降も挑めるか
}
```

**ここは判断をお願いしたい点です。**

現在、ボス級の敵は9体いますが、すべて用途が決まっています。

| 敵 | 現在の用途 |
|---|---|
| ゴブリンロード / 遺跡の守護者 / 沼のヒュドラ / 紅蓮竜イグナート | ギルドの**昇格試験** |
| 門番ガルヴァス / 四天王2体 / 魔王2形態 | **魔王城**の物語 |

**エリアボスに使える空きがありません。** 選択肢は3つです。

| 案 | 内容 | 手間 | 影響 |
|---|---|---|---|
| **A** | エリアボスは**作らない**（`boss: null`） | なし | 探索が単調になりやすい |
| **B** | 新しくボスを**4〜8体追加**する | 大 | バランス再測定が必要 |
| **C** | まずAで作り、後からBを足す | 小 | **おすすめ** |

**私のおすすめはC**です。`boss` フィールドは最初から用意しておき、
中身は `null` にします。あとからボスを足すときに、
データを1つ書くだけで済む形にしておきます。

### 4-5. 「スタミナ」について

ご指定の項目に「スタミナ消費」がありましたが、
**このゲームにはすでに AP（1日3ポイント）があります。**

スタミナを別に作ると、遊ぶ人は2つの数字を同時に気にすることになり、
「APは余っているのにスタミナが無いので動けない」という
分かりにくい状態が生まれます。

> **探索も AP を消費する（既定 1AP）ことを提案します。**

エリアごとに `ap` を変えられる形にしておくので、
「遠いエリアは2AP」といった調整は後からできます。

もし「AP とは別に、体力のような概念が欲しい」というご意図でしたら、
そのように設計し直しますので、お知らせください。

### 4-6. 地図上の位置

```
map: { col: 0, row: 0 }
```

4列 × 2行のグリッドに並べます。画像は使わず、CSSのマス目で表現します。

```
[草原]  [森]    [洞窟]   [遺跡]
[高原]  [氷牙]  [境界]   [魔界]
```

**画像を使わない理由**：ダウンロード版は1つのHTMLファイルに
すべてを収める作りなので、地図画像を入れるとファイルが重くなります。
また、スマートフォンの縦画面では、大きな地図は指で動かす操作が必要になり、
かえって遊びにくくなります。

将来、凝った地図にしたくなったときは `map` に座標（%）を入れれば
そのまま移行できる形にしておきます。

## 6. セーブデータへの追加

```
d.explore = {
  visits:   { plains: 12, forest: 3, ... }   エリアごとの探索回数
  bossDown: ['area_boss_xxx']                 倒したエリアボス
  last:     'forest'                          前回行ったエリア（画面の初期表示用）
}
```

**古いセーブデータとの互換**：この項目が無いセーブを読み込んだときは、
空の値を入れて続行します。既存の `G.State.migrate()` に
1行足すだけで対応できます（詳細は STEP 10 のセーブ設計で扱います）。

`unlocked`（解放済みエリアの一覧）は**保存しません**。
ランクとフラグから毎回計算できるので、持つと二重管理になり、ずれる原因になります。

## 11. この設計で守られること

- 戦闘エンジン（`battle.js`）には**一切手を入れません**
- `battle.js` のDOM非依存は維持されます
- 既存のゲームバランス（依頼・ショップ・学院）は**変更しません**
- 探索は**追加**であり、既存の遊び方を置き換えません
- 各段階で `npm test`（11項目）が通る状態を保ちます
