## 2. ★ 事実確認：このゲームは何もしていない

ストア公開で最も面倒なのが**個人情報の扱い**です。
そこで「実際に何をしているか」を、コードの検索と**実際の動作**の両方で確認しました。

### 調べかた

1. コードから通信・保存の処理をすべて検索
2. 実際にブラウザで起動し、**全画面を巡回して戦闘まで行い、通信を記録**

### 結果

| 調べたこと | 結果 |
|---|---|
| 外部への通信 | **0件**（全30リクエストはすべて自分自身のファイル） |
| 外部サイトへの参照 | **0件**（フォント・解析・広告いずれも無し） |
| Cookie | **なし** |
| sessionStorage | **なし** |
| 権限の要求（通知・位置情報・カメラ等） | **0件** |
| 保存しているもの | `localStorage` に**セーブデータ1件のみ**（端末内） |
| サーバー | **存在しない**（通信先が無い） |

### これが意味すること

> **このゲームは、個人情報を一切集めていません。**
> 集める手段すら持っていません（通信機能が無いため）。

**これはストア審査において非常に有利です。**
多くのアプリが躓く「何のデータを、何のために集めるか」の申告で、
**すべて「収集しない」と答えられます。**

この状態を**壊さないこと**が、以降の設計で最も大事な方針になります。

## 4. 各項目の設計

### 4-1. 音（STEP 11 と連動）

| 項目 | 既定値 | 保存先 |
|---|---|---|
| BGM ON/OFF | ON | `ta.settings` |
| BGM 音量 | 50% | `ta.settings` |
| 効果音 ON/OFF | ON | `ta.settings` |
| 効果音 音量 | 70% | `ta.settings` |

**音量は「その端末の好み」なので、セーブデータには入れません**（STEP 10・11 参照）。
セーブスロットを切り替えても音量は変わりません。

音量スライダーは**動かした瞬間に試し音を鳴らします**。
数字だけ見せても、どのくらいの大きさか分からないためです。

> **iPhoneで音が出ない場合の案内文**を、音の項目の下に小さく添えます。
> 「音が出ない場合は、本体横のマナーモードスイッチをご確認ください」
> （STEP 11 で判明した、ブラウザ版では回避できない制約のため）

### 4-2. ゲーム

| 項目 | 選択肢 | 現状 |
|---|---|---|
| 戦闘の速さ | ふつう / はやい / 最速 | **すでに存在**（`d.battleSpeed`）。設定画面に集約する |
| ダメージ表示 | ON / OFF | 新規。数字が飛ぶ演出を消せる |
| 文字の大きさ | 小 / 中 / 大 | 新規。**スマートフォンでは重要**（STEP 13 で詳しく扱う） |

**戦闘の速さはセーブデータ側**（`d.battleSpeed`）に既にあります。
これは「冒険の記録」ではなく端末の好みなので、
**本来は `ta.settings` に移すべき**です。

ただし**移すとセーブの構造が変わる**ため、STEP 10（セーブ設計）の
移行の仕組みができてから行います。それまでは**両方を読む**形にします。

### 4-3. 冒険の記録

| 項目 | 内容 |
|---|---|
| セーブ / ロード | STEP 10 で作る画面を開く |
| **データを書き出す** | セーブをテキストファイルとして保存 |
| **データを読み込む** | 書き出したファイルから復元 |
| すべて消去 | 全セーブと設定を削除（**2回確認**） |

### ★ 「書き出す／読み込む」を入れる理由

**ブラウザのデータは、消えます。**

- ブラウザの「閲覧データを削除」で消える
- スマートフォンの空き容量が足りないとOSが消すことがある（STEP 10 参照）
- 別の端末に引き継げない

**この機能があれば、遊ぶ人は自分で自分のデータを守れます。**
サーバーを持たない（＝個人情報を集めない）方針を保ったまま、
データ消失という最大の不満に答えられる、**唯一の現実的な手段**です。

実装は難しくありません。セーブは最大11KB のテキストです（STEP 10 実測）。

- 書き出し：ファイルとしてダウンロード
- 読み込み：ファイル選択 →**必ず中身を検査してから**取り込む
  （STEP 10 で作る検査の仕組みをそのまま使う）

> **読み込みの安全性**：他人が作った不正なファイルを読む可能性があるため、
> 「JSONとして読めるか」「形式が正しいか」「値が範囲内か」を
> すべて確認してから取り込みます。検査を通らなければ取り込みません。

## 5. ★ 通知について：入れないことを推奨します

ご指定の項目に「通知設定」がありましたが、
調べた結果、**このゲームには通知する内容がありません**。

### 理由

**このゲームの時間は、実時間で進みません。**

```
日付が進むのは「休息」を選んだときだけ
AP（1日3ポイント）が回復するのも、休息したときだけ
```

コードを確認しました。実時間を使っているのは次の3か所だけで、
いずれもゲーム進行とは無関係です。

| 場所 | 用途 |
|---|---|
| `state.js:22` | セーブの作成日時（記録のみ） |
| `errors.js:65,96` | エラーの記録時刻・表示間隔 |

つまり、

> **「スタミナが回復しました」「イベントが始まりました」と
> 伝えるべきことが、1つも存在しません。**

### 通知を入れた場合のマイナス

| 項目 | 影響 |
|---|---|
| 権限要求 | 起動時に「通知を許可しますか？」が出る。**現在は権限要求0件** |
| ストア審査 | 通知の用途説明が必要になる |
| プライバシー申告 | 「通知トークン」の扱いについて申告項目が増える |
| 実装 | Capacitor の追加プラグインが必要 |
| 遊ぶ人の印象 | **用もないのに通知を求めるアプリは嫌われます** |

### 推奨

> **通知は実装しません。設定項目にも出しません。**

将来、実時間で回復するスタミナや、日替わり依頼などを入れるなら、
**そのときに初めて**通知を検討します。

**もし「通知は必ず入れたい」というご意向であれば**、
まず「何を通知するか」をお決めください。
それが決まらないうちに仕組みだけ作ると、
審査で「通知の目的が不明」として差し戻される可能性があります。

## 7. 設定の保存先

```
ta.settings = {
  fmt: 1,
  bgm:     { on: true, vol: 0.5 },
  se:      { on: true, vol: 0.7 },
  battleSpeed: 2,
  showDamage: true,
  fontScale: 1.0,
  locale: 'ja',          ← STEP 7 の言語設定
}
```

- **セーブデータとは完全に分離**します
- STEP 10 の `G.Storage` を使います（アプリ化時に差し替え可能）
- 「すべて消去」でセーブと一緒に消します
- **壊れていたら既定値に戻します**（設定が壊れてゲームが起動しないのは論外）
